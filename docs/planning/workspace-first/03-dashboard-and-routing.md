# W03 — Dashboard and project-scoped routing

**Status: complete (2026-10-06).** Dependency: W02.

## Work

1. Discover managed workspaces before Git repositories. Support dashboard/project-selected/blocked states and direct registered-project startup. Invalid recognized workspace identity/configuration/registry must not become unrestricted Pi.
2. Register `/projects`, `/workspace`, and workspace status. List explicitly registered projects with readable names/paths, missing/moved status, runs, and blockers; never silently bind discovered repositories.
3. Display workspace, selected project or none, PLAN/BUILD, and workspace capacity. Without selection, disable engineering dispatch, approvals, candidate assembly/integration, and project planning writes. Mode changes affect only the selected project.
4. Capture immutable project identity/generation for every command/tool. Validate project-relative and absolute paths against that project; do not reinterpret an A path in B. Constrain actual read/search implementations and returned data, not just read/grep/find/ls names. Cross-project/private-state reads fail closed.
5. Keep the no-shell policy and dedicated `radian_git_inspect`; restrict unknown/deferred/nested/MCP/codemode execution routes. Planning writes use the verified scoped path, not Pi write/edit.
6. Preserve project config snapshots, approvals, immutable candidate checks/output roots, launcher evidence, launch authorization, owned resources, and durable cycles. Routing must not weaken them or change another project's settings/capabilities.

## Acceptance/tests

Offline/fake-host tests cover empty roots, invalid managed bindings, direct entry, no-selection actions, display/modes, traversal/absolute/link paths, arbitrary read/search inputs, unknown/nested tools, and selection changing during an awaited A operation. No deferred A operation may read/write/approve B. Existing remediation tests remain green; W06 covers additional counterexamples.

Isolated activation is not complete until W05; a dashboard alone is not project switching.

## Completion record

- **Implemented:** `src/workspace/discovery.ts` classifies Pi's cwd as `unmanaged`, `workspace`, `direct`, or `blocked` before any Git lookup; an invalid record/registry, moved record, nested or duplicate binding, an unregistered directory, or a project subdirectory inside a recognized workspace is `blocked` (every tool refused by `RH-WORKSPACE-BLOCKED`), never unrestricted Pi. The controller (`src/ui/controller.ts`) holds one explicit view per extension runtime (`unmanaged`/`blocked`/`dashboard`/`project`); execution owners live in a process-wide registry (`src/ui/workspace-runtime.ts`) with a selection generation. `/projects` lists explicitly registered projects with readable names, missing/moved state, targets, and run/decision summaries; `/workspace` and `radian_status` show workspace status; the status line shows dashboard or `MODE · project`, live workers, and workspace capacity. With no project selected, dispatch, assembly, planning writes, Git inspection, approvals, integration, mode changes, searches, and starting runs are refused (`NO_PROJECT_SELECTED`/`RH-NO-PROJECT`).
- **Routing and confinement:** commands and tools capture their view at invocation; confirmations that outlive their view return `STALE_GENERATION` and record nothing; late A writes resolve against A; A's background results go to A's view or, when another view is current, wait in A's private inbox with a payload-free notice. Radian overrides `read`, `ls`, `grep`, and `find` (Pi's supported same-name override; `src/ui/read-tools.ts`): every call resolves relative/absolute/traversal paths against the captured project root (or the workspace root minus `.radian/` on the dashboard), `read` opens with `O_NOFOLLOW_ANY`, `ls` lists without following links, and `grep`/`find` delegate to Pi's ripgrep/fd only on a validated link-free path with a project-rooted context (not offered on the dashboard). The guard refuses a read tool whose active registration is no longer Radian's, and Radian sets the active tool set per state, so `bash`, `edit`, `write`, and other tools are not even declared; nested, MCP, codemode, tool-search, and unknown calls are refused. Planning writes still use `radian_write_artifact`; selected-project instructions and cwd are installed through `before_agent_start`.
- **Tests:** `tests/unit/workspace/w03-routing.test.ts` (5) — empty dashboard and its refusals; blocked corrupt registry, invalid direct entry, unregistered directory, project subdirectory, moved record; direct entry with relative/absolute/traversal/link/sibling-project paths for read/ls/grep/find and project-rooted delegation; unknown/nested/MCP/codemode/replaced tools; a confirmation spanning a view change, a late A write, and A's result while B is current. The remediation suites (R01–R08) and other UI tests pass; one interface assertion was updated for the added confined read tools. `tests/integration/w03-dashboard.test.ts` (native offline) — at an installed workspace root, faux-model tool calls are routed by Radian: workspace reads allowed, private state/outside paths refused, shell/write/grep/dispatch undeclared or refused, dashboard prompt without project instructions.
- **Results:** typecheck exit 0; `npm test` 162/162; `npm run test:integration` 9/9.
- **Limitations:** directory listing and delegated searches re-resolve paths after validation; only a concurrent writer to the project checkout (the user, not the coordinator) could race them. Selection/restore is W05; the dashboard here is navigation, not switching.
