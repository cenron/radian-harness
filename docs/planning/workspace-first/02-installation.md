# W02 — Empty-workspace installer

**Status: complete (2026-10-06).** Dependency: W01.

## Work

1. Decouple workspace bootstrap from project registration. An existing empty non-Git directory with zero projects is valid. Install exactly one owned Radian entry into workspace `.pi/settings.json`; retain explicit project-local entries for direct access.
2. Add a thin `install.sh` delegating to the canonical installer. Resolve source assets relative to the script and the target from the displayed/confirmed caller directory or `--workspace`. Quote paths; keep harness source separate from workspace.
3. Preserve preview-first exact-plan confirmation/hash apply, source pinning, transactional ownership, status/update/remove/recover, active/unresolved-run guards, and edited/unrelated settings. Check local Node/Git/Pi prerequisites; no global installation, trust/login acceptance, or unpinned acquisition.
4. Support legacy manifests and workspace-only repeated installation/update/remove. Do not migrate active policy or automatically modify old installations.
5. Cover directory creation as well as file opens: final no-follow open does not protect missing-parent mkdir (F01). Use a safe creation design or conservative refusal; do not introduce another escape while deferring final F01 revalidation to W06.
6. Include necessary installer assets in package contents while excluding private state/evidence. Preserve the external source and user projects on removal.

## Acceptance/tests

Disposable fixtures cover zero-project CLI, empty non-Git target, spaces, invocation from another directory, repeated install, malformed/unrelated settings, stale plans, missing prerequisites/source, moved/nested/linked paths, substitution before parent creation, legacy manifests, interruption, and update/remove with no projects.

Preview writes nothing. Apply loads Radian from the workspace root without making the workspace a Git repository. Refused operations cannot mutate outside paths; edited owned material and private artifacts are retained.

## Completion record

- **Implemented:** `install --workspace <dir>` no longer needs projects; it binds the workspace itself with one owned entry in `<ws>/.pi/settings.json` (merged, unrelated settings kept), an empty registry, and manifest `radian.manifest/2` (`workspaceEntry` plus project direct-entry entries). `--project` registration still works and refuses nested projects. `install.sh` (repo root, in the package) resolves the harness from its own location, targets the displayed caller directory unless `--workspace` is given, previews, and applies only after an interactive confirmation of the exact plan or `--apply <hash>`; `src/workspace/main.ts` is the canonical entry (`scripts/radian-workspace.ts` delegates). Prerequisites (Node ≥ 22.18, Git ≥ 2.42, Pi 1.0.2) are checked read-only with an empty temporary HOME; missing tools block, nothing is installed. Repeat installs are no-op plans; nested workspaces above or below, linked owned paths, moved records, and foreign Radian-like entries are refused or reported. Legacy `radian.manifest/1` manifests are reported by `status`, kept working, and migrated only by a previewed install/update, which an active or unverifiable run blocks.
- **Directory creation (F01 design for new paths):** every installer write, rename, journal, and removal goes through `src/util/safe-dir.ts`, anchored at the canonical workspace root: content opens use `O_NOFOLLOW_ANY`, and mkdir/rename/unlink run in a short-lived helper (`safe-dir-main.ts`) that refuses unless its working directory is the exact device/inode validated by a link-refusing open, then acts on single names relative to it. A substituted parent is detected before anything changes; non-macOS refuses. The existing planning-write primitive (`confined-fs.ts`) is intentionally unchanged here; its F01 revalidation is W06.
- **Tests:** `tests/unit/util/safe-dir.test.ts` (4) — nested create/replace/remove; parent replaced by a link immediately before mkdir, rename, and unlink leaves the outside namespace and same-named outside files unchanged; linked destination/anchor/traversal refused. `tests/unit/workspace/workspace-install.test.ts` (7) — zero-project CLI preview/apply/repeat; `install.sh` from inside a path with spaces and from another directory (real prerequisite check; non-interactive preview only, apply with hash); missing prerequisites/source, unpinned source, malformed/foreign/unrelated settings; stale plan, linked `.pi`, link swapped in after preview, workspace root swapped for a link just before mkdir (nothing outside, then `recover` completes in place), nested and moved workspaces; linked target installs canonically; update/remove with no projects retaining overrides, private state, and edited entries; legacy manifest status, binding, guarded migration. The seven earlier installer tests pass unchanged. `tests/integration/w02-workspace-load.test.ts` (2, native offline) — a real `pi --mode rpc --approve` at the installed empty workspace registers `/radian` and no `.git` appears; without a trust decision Pi does not load the package and no trust file is written.
- **Results:** `npm run typecheck` exit 0; `npm test` 157/157; the two W02 integration tests pass; package dry-run (96 files) includes `install.sh`, `src/workspace/main.ts`, and the helper, with no findings.
- **Limitations:** each namespace step starts one Node process; Pi's interactive trust prompt (not the one-run `--approve` flag) is the expected user path and is not automated here. The first Pi start at the workspace shows Radian as a dashboard only from W03 onward.
